# AI 辅助开发团队推广计划

> **文档定位**：制定团队内部推广 AI 辅助开发的分阶段执行计划，包含目标、任务、培训、验收、度量。
> **配套文档**：[AI辅助开发-能力清单.md](./AI辅助开发-能力清单.md)、[AI辅助开发-风险规避策略.md](./AI辅助开发-风险规避策略.md)
> **设计原则**：参考 McKinsey《The State of AI in 2025》— 88% 组织在用 AI，仅 39% 兑现价值，差距来自**组织化改造**而非工具本身。

---

## 一、推广总目标

### 1.1 业务目标

- **短期（3 个月）**：试点团队工程效率提升 20%，PR 周期缩短 30%
- **中期（6 个月）**：全员覆盖，单测覆盖率提升至 70%+，线上缺陷率下降 15%
- **长期（12 个月）**：建立可持续的 AI 辅助开发工作流，沉淀团队 Prompt 资产，对外可输出案例

### 1.2 北极星指标

| 指标 | 当前基线 | 3 月目标 | 6 月目标 |
|------|---------|---------|---------|
| AI 工具周活率 | 0% | 70% | 90% |
| AI 协助提交的 PR 占比 | 0% | 30% | 60% |
| 平均 PR Review 周期 | TBD | -30% | -50% |
| 单测覆盖率 | TBD | +15pp | +25pp |
| 开发者满意度（NPS） | TBD | ≥ 30 | ≥ 50 |

> ⚠️ 基线数据需在试点启动后第 2 周回填。

### 1.3 反指标（出现即警报）

- **AI 生成代码缺陷率高于人工** → 验证机制缺失，立即暂停推广
- **开发者抱怨"AI 让我变笨了"** → 过度依赖，需回归训练
- **PR Review 周期反而变长** → AI 输出质量差，需调优 Prompt
- **安全事件** → 立即触发风险评估流程

## 二、推广阶段划分

采用 **"试点 → 推广 → 深化"** 三阶段模型，每阶段都设硬性验收门槛。

```
┌──────────────┬──────────────┬──────────────┐
│  Phase 1     │  Phase 2     │  Phase 3     │
│  试点验证     │  全员推广     │  深化沉淀     │
│  Month 1-3   │  Month 4-6   │  Month 7-12  │
├──────────────┼──────────────┼──────────────┤
│ 1 个试点团队  │ 全部研发团队  │ 跨职能延伸   │
│ 建立基线      │ 标准化流程    │ 资产沉淀     │
│ 工具选型      │ 培训认证      │ 对外输出     │
└──────────────┴──────────────┴──────────────┘
```

## 三、Phase 1：试点验证（Month 1-3）

### 3.1 阶段目标

- 验证 AI 工具在真实业务场景下的效率收益
- 建立可量化的基线数据
- 沉淀首批最佳实践与反面案例
- 锻炼 3-5 名内部 AI Champion

### 3.2 试点团队选择标准

| 维度 | 要求 |
|------|------|
| 团队规模 | 5-8 人（含 1 名 Tech Lead） |
| 业务类型 | 涵盖新功能开发 + 维护性工作 |
| 技术栈 | 与公司主流栈一致 |
| 团队意愿 | Tech Lead 主动申请，成员接受度高 |
| 业务压力 | 中等（不能是着火的团队，也不能是闲散团队） |

### 3.3 工具选型清单

试点期建议**同时引入 2 类工具对比**：

| 工具类别 | 推荐 | 试点用途 | 预算参考 |
|---------|------|---------|---------|
| IDE 内嵌补全 | GitHub Copilot / Cursor Pro | 行内补全、片段生成 | $10-20/人/月 |
| Agent 编码 | Claude Code / Cursor Agent | 复杂任务多文件改动 | $20-30/人/月 |
| PR Review | CodeRabbit / Graphite | 自动 PR 审查 | $15-25/人/月 |
| 文档辅助 | Claude.ai / ChatGPT Plus | 方案设计、文档草拟 | $20/人/月 |

> 试点预算：5 人 × 4 工具 × 3 月 ≈ 1.2 万-1.8 万元

### 3.4 Month 1：准备与启动

| 周次 | 任务 | 负责人 | 产出 |
|------|------|-------|------|
| W1 | 工具采购、账号开通、权限配置 | IT + Tech Lead | 账号清单 |
| W1 | 制定试点 OKR、基线指标采集方案 | Tech Lead + PM | OKR 文档 |
| W2 | 风险评估、IP 合规审查、安全策略制定 | 法务 + 安全 | 风险规避策略文档 |
| W2 | 建立 `.cursorrules` / `CLAUDE.md` / Copilot 指令文件初版 | Tech Lead | 指令文件 |
| W3 | 试点团队 2 天集中培训（见 §5） | Champion 候选 | 培训完成 |
| W3 | 试点项目实战启动 | 全员 | 第一个 AI PR |
| W4 | 第一轮复盘、问题归集 | Tech Lead | 月度报告 |

### 3.5 Month 2：实战磨合

| 任务 | 详情 |
|------|------|
| 每日站会新增 "AI 卡点" 议题 | 成员分享遇到的问题 |
| 每周 Champion 周会 | 跨团队同步最佳实践 |
| Prompt 库初建 | 用 Notion / Wiki 沉淀有效 Prompt |
| 月中度量 | 采集 PR 周期、覆盖率、缺陷率数据 |

### 3.6 Month 3：试点验收

**硬性验收门槛（全部满足方可进入 Phase 2）**：

- [ ] AI 工具周活率 ≥ 70%
- [ ] PR 周期较基线缩短 ≥ 20%
- [ ] 单测覆盖率较基线提升 ≥ 10pp
- [ ] AI 生成代码缺陷率 ≤ 人工缺陷率
- [ ] 开发者 NPS ≥ 30
- [ ] 无安全/IP 事件
- [ ] 产出至少 5 个最佳实践案例 + 3 个反面案例

**验收方式**：
1. Tech Lead 提交《试点总结报告》
2. PM 组织验收评审会（含技术委员会、安全代表、法务代表）
3. 4 名独立审查者按 [深度审查模板] 评分，需 3/4 通过

### 3.7 试点退出机制

若任一情况发生，**立即暂停试点并复盘**：
- AI 生成代码导致线上 P0/P1 故障
- IP 侵权风险被实际触发
- 开发者 NPS 低于 0（团队抵触）
- 工具成本 / 收益比 < 1:2

## 四、Phase 2：全员推广（Month 4-6）

### 4.1 阶段目标

- 全员覆盖（研发、测试、运维、PM 均纳入）
- 建立标准化 AI 辅助开发工作流
- 全员完成基础培训认证
- 修订研发流程规范，纳入 AI 工具

### 4.2 推广节奏

| 月 | 推广团队 | 工具组合 | 培训批次 |
|----|---------|---------|---------|
| M4 | 2 个新团队加入 | 试点验证的优胜组合 | 第 2 期培训 |
| M5 | 再扩 3-4 个团队 | 标准化工具包 | 第 3-4 期培训 |
| M6 | 全员覆盖 | 标准化工具包 | 第 5-6 期培训 |

### 4.3 标准化建设

#### 4.3.1 指令文件标准

每个仓库根目录必须有：

- `CLAUDE.md` 或 `.cursorrules`（AI 工具指令文件）
- `docs/ai-conventions.md`（AI 使用约定，包括哪些场景可用、哪些禁止）

指令文件内容遵循 [能力清单 §4.1](./AI辅助开发-能力清单.md#41-claudemd--cursorrules--copilot-指令文件最佳实践) 的 Anthropic 原则。

#### 4.3.2 工作流标准

```
需求 → Plan Mode 探索 → 方案设计 → AI 协助实现 → 自检 → PR → AI Review → 人工 Review → 合并
```

- **Plan Mode 必须使用**：多文件改动、架构调整、不熟悉的代码
- **Plan Mode 可跳过**：typo、日志行、重命名（一句话能描述的 diff）
- **PR 强制要求**：AI 生成的代码必须人工 Review，PR 描述注明 "AI-assisted"

#### 4.3.3 培训认证标准

全员需通过 **"AI 辅助开发基础认证"**：

- 在线课程（2 小时）
- 实操考核（在真实仓库完成 1 个 AI PR）
- 通过率 ≥ 80% 方可独立使用 AI 工具

### 4.4 Phase 2 验收

- [ ] 全员培训覆盖率 ≥ 95%
- [ ] 认证通过率 ≥ 80%
- [ ] AI 协助 PR 占比 ≥ 40%
- [ ] PR Review 周期较基线缩短 ≥ 30%
- [ ] 单测覆盖率较基线提升 ≥ 20pp
- [ ] 标准化指令文件覆盖所有核心仓库
- [ ] Prompt 库沉淀 ≥ 50 条

## 五、培训体系

### 5.1 培训分级

| 等级 | 对象 | 时长 | 内容 |
|------|------|------|------|
| **L1 基础认证** | 全员 | 4 小时 | 工具入门、Prompt 基础、风险须知 |
| **L2 进阶** | 研发 + 测试 | 8 小时 | Plan Mode、TDD、调试、代码审查 |
| **L3 高级** | Champion 候选 | 16 小时 | Agent 编排、MCP、Skills 开发、Hooks |
| **L4 专家** | Champion | 32 小时 | 训练数据、模型评估、安全加固、对外输出 |

### 5.2 L1 基础认证大纲（4 小时）

| 时段 | 模块 | 内容 |
|------|------|------|
| 0:00-0:30 | 开场 | AI 能力边界、案例展示 |
| 0:30-1:30 | 工具操作 | IDE 补全、Chat、Agent 三种模式实操 |
| 1:30-2:30 | Prompt 基础 | SCQA、上下文、约束、验证标准（见能力清单 §4） |
| 2:30-3:00 | 风险须知 | 幻觉、IP、安全、隐私（见风险规避策略） |
| 3:00-4:00 | 实操考核 | 在沙箱仓库完成 3 个任务 |

### 5.3 L2 进阶大纲（8 小时）

| 模块 | 重点 |
|------|------|
| Plan Mode 工作流 | 探索→规划→实现→提交四阶段实战 |
| TDD with AI | 让 AI 先写失败测试，再实现 |
| 调试技巧 | 贴报错、根因定位、复现脚本 |
| 代码审查 | AI Review + 人工 Review 协同 |
| 重构 | 大规模重构的安全模式 |
| 文档生成 | API 文档、ADR、变更日志自动化 |

### 5.4 Prompt 库建设

#### 5.4.1 结构化 Prompt 模板

每个 Prompt 包含 5 个字段：

```markdown
### Prompt 名称
- **场景**：何时使用
- **输入**：需要提供什么（代码、报错、需求）
- **约束**：不能做什么
- **验证标准**：如何判断输出正确
- **示例**：成功使用案例
```

#### 5.4.2 Prompt 库分类

| 类别 | 示例 |
|------|------|
| 代码补全 | "实现 XX 函数，遵循 YY 模式" |
| 调试 | "贴报错，分析根因并修复" |
| 重构 | "将 XX 模式重构为 YY，保持行为不变" |
| 测试 | "为 XX 函数写边界用例，覆盖 null、空、越界" |
| 文档 | "为 XX 模块生成 API 文档，包括示例" |
| 审查 | "审查此 PR，关注安全、性能、可维护性" |
| 规划 | "用 plan mode 分析 XX 改动的影响面" |

### 5.5 Champion 制度

每个团队培养 1-2 名 Champion，承担：

- **教学**：组织团队内 L1/L2 培训
- **答疑**：团队内 AI 使用问题的一线支持
- **资产沉淀**：维护 Prompt 库、指令文件、案例库
- **反馈**：向中心化 AI 小组反馈工具问题与改进建议

Champion 激励：
- 工具订阅免费
- 季度专项奖金
- 对外演讲机会
- 晋升加分项

## 六、Phase 3：深化沉淀（Month 7-12）

### 6.1 阶段目标

- 沉淀团队级 AI 资产（Skills、Hooks、MCP 服务器）
- 跨职能延伸（PM、设计、运维）
- 对外输出案例与方法论

### 6.2 深化方向

| 方向 | 具体动作 |
|------|---------|
| **Skills 开发** | 将团队最佳实践封装为 Claude Skills / Cursor Rules |
| **Hooks 自动化** | 提交前自动 lint、安全扫描、commit message 校验 |
| **MCP 集成** | 接入 Jira、Confluence、Grafana、Sentry，让 AI 直接读写运维数据 |
| **专属模型微调** | 基于团队代码库微调（需评估 ROI） |
| **跨职能延伸** | PM 用 AI 写需求、设计用 AI 出方案、运维用 AI 写 SOP |

### 6.3 资产沉淀清单

| 资产类型 | 仓库 | 维护人 |
|---------|------|-------|
| Prompt 库 | `team-prompts` | Champion 轮值 |
| Skills 库 | `team-skills` | AI 小组 |
| Hooks 库 | `team-hooks` | AI 小组 |
| 案例库 | `team-cases` | 全员贡献 |
| 培训材料 | `ai-training` | L3+ Champion |
| 指令文件模板 | `ai-templates` | AI 小组 |

### 6.4 对外输出

- 公司技术博客：每月 1 篇 AI 实践文章
- 行业大会：年度 1-2 场对外演讲
- 开源贡献：将通用 Skills / Hooks 开源
- 客户案例：与市场部合作产出客户案例

## 七、组织保障

### 7.1 角色与职责

| 角色 | 人数 | 职责 |
|------|------|------|
| **Sponsor** | 1（CTO/VP） | 资源调配、跨部门协调、最终决策 |

| **安全代表** | 1 | 安全策略制定、事件响应 |
| **法务代表** | 1 | IP 合规、数据合规审查 |
| **PMO** | 1 | 度量、报告、流程治理 |

### 7.2 治理机制

| 机制 | 频率 | 参与人 |
|------|------|-------|
| Champion 周会 | 每周 | Champion + AI 小组 |

| 工具选型评审 | 半年 | AI 小组 + 代表团队 |

## 八、度量与报告

### 8.1 度量维度

| 维度 | 指标 | 采集方式 |
|------|------|---------|
| **采用率** | 工具周活率、AI PR 占比 | 工具后台 + Git 统计 |
| **效率** | PR 周期、Lead Time、部署频率 | DORA 指标 |
| **质量** | 缺陷率、覆盖率、Review 通过率 | 研发平台 |
| **满意度** | NPS、CSAT | 季度问卷 |
| **成本** | 工具订阅、培训、激励支出 | 财务 |
| **风险** | 安全事件数、IP 事件数 | 安全 + 法务 |

### 8.2 报告节奏

- **周报**：Champion 周会同步关键指标
- **月报**：项目负责人提交 Sponsor
- **阶段报告**：每阶段末提交技术委员会
- **年度白皮书**：12 月底产出
